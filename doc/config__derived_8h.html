Detailed Description

The configuration as the firmware uses it: the settings, and what is built from them.

The code includes this file, never config.h directly. config.h only holds the settings; here come the values derived from them and the objects built from them:

  • the calibration of the board (calibration.h): f_powerCal and f_voltageCal of PCB_VERSION, in the per-phase arrays the code uses;
  • the sample sets per mains cycle, and the counter of those of a datalog period;
  • the number of remote loads and units, from the load map;
  • remoteLoads, the remote-load controller, which holds the transmission state;
  • relayDiverter, the relay engine, from relays;
  • overrideTable and boostSchedule, the bitmasks that overridePins and scheduledBoosts force, once LOAD(), RELAY() and ALL_...() are turned into pins;
  • tempSensors, which reads the sensors of temperatureSensing.

◆ remoteLoads

RemoteLoadCore< NO_OF_REMOTE_UNITS > remoteLoads {}
inline

The one and only remote-load controller.

Declared non-const on purpose: it holds the per-unit transmission state. RemoteLoadCore has a constexpr default constructor and brace-or-equal member initialisers, so this object is constant-initialized. It therefore lands in .bss with no entry in .init_array, and --gc-sections drops it outright when no remote unit is configured.
