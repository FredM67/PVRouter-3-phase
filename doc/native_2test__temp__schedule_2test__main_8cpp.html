Detailed Description

Native unit tests for temp_schedule.h: which 1-Wire transaction runs on which mains cycle.

The main loop asks the schedule once per mains cycle, when it sees the new cycle, and runs the transaction it gets: the conversion of every sensor, then, once the conversion time has passed, the three transactions of each sensor's read. One transaction per cycle at most, only on a cycle seen on time (the loop idle when it began), and the round over well before the end of the datalog period, whose values it gives.

A datalog period of the main loop: the round must be over before the cycle that ends the period, whose ISR copies run ~1248 µs before the new cycle is flagged.

The cycle after each per-second tick is late (the per-second work and the display may run past the next tick).
